# Unified operational protocol v1 — CDF / OpenCode
Scope: only the repository and lane authorized by the invoking task. No canon, production data, credentials, new services, GitHub Pro, or visibility changes. Never merge ops/task-checkpoints-v1 into main. Existing task-specific restrictions take precedence; the integration workflow is the sole participating writer of main, not a server-enforced protection.

## Authority and state
- Actual GitHub refs, Issue/PR state and execution evidence outrank snapshots. checkpoints.json is continuity/lease metadata; integration-queue.json is generated candidate metadata, not approval; request files are commands, not receipts; Actions jobs/artifacts are evidence. A task ID is not a PR number. completed means that task's acceptance, not merged/deployed. No new task just to repeat a terminal result.
- Start with checkpoint, current main and only pertinent PR/Issue. Prefer native Code Mode parallel reads; reuse compose.mjs via Agent context on demand only when needed (CAS context-request.json: project short name, lane or independent pr, operation, up to 4 allowed steps, request_id). No full histories, raw bodies or logs. COMPLETE_READS is not task acceptance. Recheck exact refs and checkpoint blob; targeted_tree_match requires queue tree as well as head/base. Missing/stale evidence is not PASS. Queue current only for matching main and PR head.
- Select one useful objective (WIP as defined by task). Resume recoverable or expired active only after revalidation; blocked only with material new evidence. Check prior execution/session before retry. If no useful action, do not reserve or generate work.

## Reservation and recovery
Use checkpoints.json policy.write/recovery/checkpoint on exact ops branch. GitHub fetch_file → update_file with returned blob SHA; preserve all lanes and other fields. Increment revision for every mutation; claim owner unique to execution, generation=incremented revision, lane and real UTC expiry +45m. Live foreign lease means no participating writes; malformed lease means block. Confirm ownership/generation/expiry and target SHA before consequential write. Renew if needed. Persist first useful evidence and material milestones (task_id, objective, acceptance, PR/Issue, branch, head/base SHA, completed/pending, evidence references, blockers, next_action, session/operation). Release own lease by CAS when paused or done. If timeout/conflict, reread actual state before retry. Two no-progress attempts → blocked until new evidence. Do not hold lease while awaiting CI or external approval. Never record secrets or canon.

## Validation and queue
Use validation_v1 evidence and validator version; exact identity and tree required for reuse. Static PASS/CACHED and targeted PASS are not full product acceptance. If missing material evidence, CAS validation-request.json using project, pr, base, head, request_id; targeted only if needed. Retrieve actual run by request commit, jobs/receipt, persist compact evidence. No duplicate active requests. For queue refresh when main/head/new material review changes, CAS integration-request.json (schema agent-integration-refresh/v1, main, stable request_id, reason), read generated snapshot and run; never edit it directly. Keep NO MERGE, NO FUSIONAR, STOP_LIVE, experiments, draft and unresolved reviews blocked. Do not close by mere age or overlap. Reuse focused exact-tree evidence; never infer deploy/merge from it.

## Handoff and integration
Only eligible non-draft candidates with real functional acceptance, no prohibitions, verified dependencies and separate deployment clearance can be handed off within authorized lane scope. Existing general owner authorization allows conditional integration, not arbitrary release. A comment from shared owner-account connector is agent evidence, not personal consent. For a reviewed eligible PR use marker AGENT_REVIEWED base=<SHA> head=<SHA> tree=<SHA> in PR comment, explicitly attributed to agent. Store its URL and exact handoff_v2 in checkpoint integration_v1 with pr, base, head, tree, request_id, review_reference, lane, task_id, functional_acceptance:"PASS", review_origin:"agent", evidence array of GitHub URLs, deployment object identical to request. Matching lane has task_id/pr/base_sha/head_sha and completed or recoverable state; preserve objective and acceptance. No marker or PASS absent actual review. Release own reservation before handing off; CAS request, no duplicate pending operation.
Request main-integration-request.json schema agent-main-integration/v1: enabled:true, pr, base, head, tree, request_id SHA256(repo:pr:base:head:tree), acceptance {reviewed:true,reference:exact PR comment URL,lane,scope:"exact-head-base-tree"}, deployment {mode,reference,observed_at:UTC epoch seconds}, dependencies array of exact integrated PR numbers. Read integrate_exact.py for strict contract. For CDF CLOUD NO_DEPLOY only README.md/docs/** with a live Cloudflare trigger assessment <=2h, reference cloudflare-live-no-deploy:8f152306-cca8-44c4-ad7b-1b1330738554; check all pertinent actual triggers and candidate paths. Attestation is operational trust, not independent cryptographic proof. WorkBench/OpenCode main can deploy on any path; no release inferred. EXPLICIT_RELEASE needs independently verified specific user instruction recorded by authorized operator in release_grant_v2 (origin:"explicit-user-instruction-verified-by-operator", exact identity, authorized:true, reference matching request) plus matching DEPLOY_AUTHORIZED marker. Routine agents never create release grants or claim user personally approved. If no such grant, block deployment-bearing candidate. Poda never hands off.
Agent exact main integration uses trusted ops code; separate read-only full CI on exact combined tree; after success checks live refs, claims integration lease and pushes exact-base fast-forward only. No agent direct merge/push, no product code in write job. Main external writers still possible; CAS rejects stale base but cannot stop outside writers or ABA. Reconcile receipt after timeout, never reapply blindly. Workflow persists receipt and refreshes queue/checkpoint; if publication incomplete, verify actual parents/tree, reconcile when lease free. Do not overwrite active requests; after consumed and verified, disable request by CAS. No eligible candidate: enabled:false, no full tests or writes. No permission or deploy changes from routine lanes. OpenCode auxiliary only, respect supervisor stop; do not inject credentials or bypass policies.
